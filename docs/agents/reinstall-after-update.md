# 更新后重安装

适用：更新代码后安装本机应用、重新安装、清理旧版本、修复辅助功能授权。按顺序执行，完成末尾验收后再报告成功。

## 唯一安装位置

- 安装实例：`/Applications/CodexUsageFloat.app`。
- 应用标识：`local.codex.usagefloat`；可执行文件：`Contents/MacOS/CodexUsageFloat`。
- 桌面、Dock、登录启动和其他快捷入口统一指向安装实例。仓库内 `.app` 和裸二进制仅是构建中间产物，交付前移到废纸篓。
- 清理以应用标识和实际路径为准，覆盖改过名字的副本；保留仓库源码、资源、用户设置和其他应用。

## 1. 盘点与同步

1. 记录工作区状态、当前提交、已运行进程的完整可执行路径、现有登录启动配置及应用签名。保护未提交改动；需要同步 `main` 时使用 fetch 和快进，合并 PR 仅在用户已要求时执行。
2. 用 `mdfind 'kMDItemCFBundleIdentifier == "local.codex.usagefloat"'` 找候选，再扫描可访问目录补足未索引副本：用户目录（含 Desktop、Downloads、Applications、隐藏目录及 worktree）、`/Applications`、`/Users/Shared`、临时/备份目录、其他已知安装目录和已挂载卷。排除废纸篓，去重真实路径，避免符号链接循环。
3. 对每个候选读取 `Contents/Info.plist`，确认应用标识；检查进程路径、Finder 替身/符号链接、Dock 和 LaunchAgent 引用，补查发现的新路径。检查仓库及已知构建目录的裸 `CodexUsageFloat` 可执行文件。
4. 所有非唯一安装位置的同标识副本均纳入清理，包括同版本副本、仓库构建和临时回滚备份。记录不可访问/只读位置；有残留时明确报告位置，不能声称已完成全盘清理。

## 2. 构建与安装

1. 对待安装代码执行适用验证（行为测试入口：`./tools/test.sh`），然后运行 `./run.sh --build-only`。这个任务始终使用 build-only；默认 `./run.sh` 会直接启动仓库副本。
2. 用 `codesign --verify --deep --strict CodexUsageFloat.app` 验证构建。记录待安装可执行文件哈希及 `codesign -dr - CodexUsageFloat.app` 输出。有可验证的同一源码构建时可复用，避免无意义重建和重复授权。
3. 暂停已存在且会启动本应用的登录任务，关闭所有已确认的 Codex Usage Float 进程。确认退出后替换安装实例。先保留可恢复的旧构建，安装失败时恢复；回滚副本放在废纸篓或不会被当作应用打开的压缩包内。
4. 先把旧安装包移到废纸篓，再使用 `ditto CodexUsageFloat.app /Applications/CodexUsageFloat.app` 复制到干净位置，避免合并旧包留下过期资源；复制失败时恢复旧包。再次验证安装包签名，并用 `cmp` 或 SHA-256 确认已安装可执行文件与最终构建一致。
5. 若此前已启用登录启动，执行 `./start-on-login.sh` 更新现有配置。此前未启用时保持用户选择。检查 plist 引用 `/Applications`，日志落在用户 Library；清理指向旧路径的重复任务。
6. 只使用 `open -n /Applications/CodexUsageFloat.app` 启动，记录新 PID。验证只有一个应用进程且完整路径为安装实例；`open` 命令成功本身不算重启验证。

## 3. 移除副本与旧入口

1. 安装实例启动正常后，对步骤 1 确认的其他应用副本先执行系统 LaunchServices 的 `lsregister -u <旧应用路径>`，再移到系统废纸篓，处理重名，保留可恢复性。未注册的备份可能返回 `-10814`，核对注册列表后继续清理；其他错误应核查。使用系统文件操作或 `FileManager.trashItem`；保护 `/Applications` 安装实例及其真实目标。清理构建产生的仓库 `.app`、裸二进制和临时备份。
2. 清理或重定向引用旧副本的桌面替身、符号链接和 Dock 入口。用户需要保留快捷入口时，将其目标改为安装实例；不会解析的入口先报告并核对，不凭名称猜测删除。
3. 用 `lsregister -f /Applications/CodexUsageFloat.app` 注册安装实例；保持其他应用注册信息。
4. 重复候选盘点和路径检查。废纸篓外只允许安装实例，以及指向它的快捷入口。Spotlight 可能缓存已移走路径，逐项检查文件是否实际存在。

## 4. 辅助功能授权

1. 读取实际运行应用的主窗口：权限说明消失才表明应用已识别授权。系统设置中开关为“开”不能替代应用状态验证。
2. 若仍有权限提示，在“系统设置 → 隐私与安全性 → 辅助功能”中右键应用，选择“在访达中显示”，核对记录指向安装实例。保持最终构建签名不变，再尝试重启该安装实例，复查提示。
3. 若提示仍在，先取得当前操作所需的明确授权，再仅移除该应用的旧记录，使用 `+` 按完整路径添加 `/Applications/CodexUsageFloat.app` 并允许。本流程文档本身不代替系统权限操作所需的用户确认；复用当前会话中已经明确授予的确认。
4. 需要系统支持的重置时，只针对该标识执行 `tccutil reset Accessibility local.codex.usagefloat`，随后重新添加安装实例。优先使用设置界面移除旧行；重置会撤销批准，本身不会授予权限。保持其他应用授权及系统保护设置。
5. 重新读取运行应用，确认权限提示消失。授权完成后保持同一构建，不再编译或签名；若再次替换构建，重新执行本节验证。

## 5. 交付验收

- 代码：报告安装来源提交；用户要求同步时，本地 `main` 与远端一致，未提交改动有明确说明。
- 安装：签名有效、可执行文件匹配；只有一个运行进程，路径为 `/Applications/CodexUsageFloat.app/Contents/MacOS/CodexUsageFloat`。
- 清理：列出已移到废纸篓的副本；有效快捷入口和已有登录启动均指向安装实例。逐项报告无法清理的位置。
- 权限：实际应用主窗口已无 Accessibility 提示。
- 浮层：通过黄色按钮收起主窗口，聚焦 Codex，确认本应用的 `Codex Usage Follow Overlay` 窗口出现，显示真实英文额度（如 `Weekly 7% left`）。权限通过不能替代浮层显示验证。
- 工具无法观察或操作目标时，请用户完成对应实测，保留“待验证”状态；不能以构建、测试或进程存活替代显示验证。
- 报告重启 PID、权限及浮层结果和唯一启动位置。单独说明仍需用户动作的步骤；不把待授权/待验证写成全部完成。
